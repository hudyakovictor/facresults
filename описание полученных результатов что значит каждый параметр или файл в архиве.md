## Корень `stage1/`

### `main_timeline.csv` — хронологическая ось всего датасета
Создаётся `app6/stage1/engine.py` после `atomic_photo_directory`. Колонки (проверено на `stage1/main_timeline.csv`):

`photo_id,date,same_date_sequence,pose_bin,pitch,yaw,roll,source_filename,source_relative_path,date_provenance_status,exif_date,date_delta_days,source_claimed_date,source_claimed_delta_days,date_conflict_sources,source_provenance_status,source_url,archive_url,perceptual_dhash,near_duplicate_of,geometry_status,segmentation_status,uv_status,combined_visible_fraction,skin_mask_coverage,uv_observed_coverage,chronology_index_global,chronology_index_in_pose`

Нюансы хронологии:
- `date` — **из имени файла** `naming.py:30` первичный источник. EXIF **не читается** `app6/README.md:2`. Формат строго `YYYY_MM_DD`, парсится regex `19\d2|20\d2`/`\d1,2`.
- `same_date_sequence` — `sequence` из `naming.py:51` (`(2)`→2, `_2`→2, иначе 1). `1999_08_16(2).jpg` и `1999_08_16_2.jpg` → один `canonical_stem=1999_08_16_2` но разные `photo_id` из-за хеша.
- `pose_bin` + `pitch/yaw/roll` — `yaw` из `reconstruction.npz:angle_deg_pitch_yaw_roll` → `config.POSE_BINS` → `geometry.classify_pose`. `canonical_yaw` центра бина.
- `chronology_index_global` / `in_pose` — порядок сортировки по `date, sequence` для Stage2 `pair_adjacent`/`anchor`.
- `date_conflict`/`perceptual_dhash`/`near_duplicate_of` — провенанс даты и дедупликация; Stage2 гейтит `date_provenance_limited`.
- Фильтр: в эту копию попадают только `validation.status==complete` `validator.py:290`, иначе фото уходит в `_failures/`.

## Как проверить хронологию верно

1. Бери `main_timeline.csv` отсортируй по `date, same_date_sequence` (`chronology_index_global`). Фильтруй `geometry_status=valid`.
2. Для пары фото внутри **одного `pose_bin`** сравни **только** `ldm*_chronology.csv` (не `raw`, не `aligned`). Разный `pose_bin` — разные `canonical_yaw` → сравнивать нельзя без кросс-биновой гейтинга Stage2 `pose_policy`.
3. Учитывай `corner_lift_ioc>0.005` → `smile_detected` и `jaw_open_ratio>0.28` → `jaw_open_detected` `config.py:63,69` — Stage2 гейтит `expression_mismatch`.
4. Смотри `chronology:alignment_quality`, `residual_*_deg`, `visible_landmarks_106/134` — низкий `alignment_quality` или малый `visible` → недостоверно (Stage2 `quality_gate`).
5. `canonical_stem` + `sequence` различают `1999_08_16.jpg` vs `1999_08_16(2).jpg` → `1999_08_16_2` (sequence 2) `naming.py:60`.
6. Для Stage2 `noise` нужен same-day (`same_date_sequence`>1) — без него `no_reference` (как в тесте `stage2_v2` 6 пар).
